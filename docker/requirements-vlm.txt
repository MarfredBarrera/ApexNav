# --- lavis's actual import requirements --------------------------------------
# lavis is installed with --no-deps because its declared dependency list has rotted:
# it requires an *unpinned* spacy, which now resolves to a version needing
# thinc>=8.3.12 / Python>=3.10, making the whole env unsolvable. Pinning spacy to the
# last line that still supports 3.9 (3.7.x, which wants thinc<8.3.0) fixes that.
#
# The rest of this block is what `from lavis.models import load_model_and_preprocess`
# actually pulls in, determined by resolving the import chain module by module. lavis's
# other declared deps (streamlit, plotly, opendatasets, pycocoevalcap, ...) are not on
# that path. spacy IS on it - lavis/models/__init__.py imports img2prompt_vqa, which
# imports spacy at module level - so it cannot simply be dropped.
#
# --no-deps also removes the transformers conflict the README's install order produces
# (lavis pins <4.27, ApexNav pins 4.43.2 - upstream issues #22/#23). With --no-deps
# there is nothing to conflict, and 4.43.2 is what actually gets used either way.
